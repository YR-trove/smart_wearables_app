Here is the exact structure and sequence of the BLE packets being sent during the sensor readings:

1. IMU Metrics Packet (Every 1 Second)
This packet is sent unconditionally every 1000 ms, keeping the app updated on motion tracking.
Size: 34 bytes
Structure:
Byte 0: Message Type (0x50 / BLE_MSG_IMU_METRICS)
Byte 2: Step Count (Cumulative steps since the live-mode session started)
Byte 2: Reserved (0x00)

2. Light Metrics Packet (Every 7 Seconds)
This packet is dispatched at the very end of the 7-second sensor superframe (the SENSOR_PHASE_ENV_END phase). To save power, it is only sent if the lighting values have changed since the last transmission.
Size: 4 bytes
Structure:
Byte 0: Message Type (0x51 / BLE_MSG_LIGHT_METRICS)
Byte 1: Exposure Class (0x00 = Dark to 0x04 = Outdoor)
Bytes 2-3: Blue / Clear ratio (16-bit unsigned integer, scaled by 10000)

3. Microphone Metrics Packet (Every 7 Seconds)
Like the light packet, this is also sent at the end of the 7-second superframe, and only if the acoustic environment has changed.
Size: 4 bytes
Structure:
Byte 0: Message Type (0x52 / BLE_MSG_MIC_METRICS)
Byte 1: Environment Class (0x00 = Very Quiet to 0x06 = High Exposure/Dangerous)
Bytes 2-3: LAeq value × 10 (16-bit little-endian integer. E.g., 653 = 65.3 dB)

4. Connection Event Packet (On Connect/Disconnect)
This is an asynchronous packet sent immediately when the RN4871 Bluetooth module signals a connection change, so the app's UI can update instantly.
Size: 2 bytes
Structure:
Byte 0: Message Type (0x53 / BLE_MSG_CONNECTION_EVENT)
Byte 1: Event Code (0x01 = Live Mode Start, 0x02 = Live Mode Stop)
